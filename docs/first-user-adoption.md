# First-user adoption plan

The next growth target is not a large star count. It is the first group of external developers who use the dataset for a real task and can explain why it was useful.

## Priority 1: developer utility

Make the five-minute path obvious: clone, load `data/repositories.json`, filter it, and use `html_url` for the upstream source. Keep examples small and dependency-light.

Success evidence: external projects or issues referencing an actual use of the dataset.

## Priority 2: integrations

Approach maintainers of repository discovery tools, developer catalogs, AI tooling, research projects, and open-source dashboards only when the registry clearly fills a data need. Offer the open dataset first; do not require sponsorship or payment for basic use.

Success evidence: at least one independent integration, fork, or documented downstream use.

## Priority 3: research and writing

Publish technical notes or demonstrations that answer real questions with the snapshot: language distribution, repository popularity, category coverage, or changes between snapshots. Link to the exact snapshot and methodology.

Success evidence: external references, citations, or reproducible analyses.

## Priority 4: contributor loop

Use GitHub Issues and pull requests for data-quality problems, examples, documentation, and integrations. Respond with evidence and keep the collection rules independent of individual requests.

Success evidence: meaningful external fixes or improvements.

## Priority 5: sponsor validation

Do not ask companies to sponsor an abstract idea. First identify organizations that actually use the data or care about developer ecosystem infrastructure. Present a concrete maintenance or capability milestone that sponsorship would fund.

Success evidence: a sponsor who can state a genuine reason for supporting the project.

## Weekly operating loop

1. Review data-quality and feature requests.
2. Improve one high-value developer path.
3. Publish one concrete use case or research example.
4. Reach out to a small number of relevant communities or maintainers with useful, non-spammy material.
5. Record actual adoption evidence.
6. Prioritize roadmap work from that evidence.

Avoid buying stars, mass-posting links, fake testimonials, automated engagement, or any tactic that creates attention without product value.
