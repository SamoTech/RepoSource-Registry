# Content strategy

RepoSource content should demonstrate technical utility. The primary audience is developers, data engineers, researchers, and maintainers.

## High-value themes

- Building reproducible repository discovery datasets.
- Working with GitHub repository metadata without treating it as live truth.
- Language and topic distribution analysis.
- Data quality and missingness in repository metadata.
- Designing local indexes over public JSON datasets.
- Using repository metadata in retrieval and RAG systems.
- Reproducible open-source ecosystem analysis.
- Practical ETL patterns for large static datasets.

## Content format

Prefer a technical article, notebook, example, or short research note that contains:

`QUESTION → DATA → METHOD → RESULT → LIMITATIONS → REPRODUCTION`

Link to the exact dataset version and source files used.

## SEO rule

Build a small set of durable pages around dataset, schema, methodology, examples, research, and discovery. Do not generate large numbers of thin pages solely for search traffic.

## Editorial standard

Every claim should be traceable to the dataset, repository documentation, or a cited upstream source. Avoid inflated language, fake adoption, unsupported authority claims, and generic startup copy.
