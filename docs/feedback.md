# Feedback

RepoSource Registry should make it easy to report concrete problems and useful requests.

## Report categories

- Data quality
- Missing or malformed metadata
- Schema questions
- Documentation problems
- Discovery/search UX
- Example requests
- Research questions
- Integration requests

## Good feedback includes

- the affected file or page;
- the repository record or field when relevant;
- the expected behavior;
- the observed behavior;
- the snapshot/version used;
- a reproducible example where possible.

## Contribution path

`REPORT → TRIAGE → REPRODUCE → FIX → TEST → RELEASE`

Data changes should remain traceable to the collection and validation process. Do not edit generated records manually to solve an isolated downstream issue.

## Privacy

Do not include secrets, credentials, private data, or personal information in public issues. Security-sensitive reports belong in the process described by `SECURITY.md`.
