# Community growth

RepoSource Registry should earn attention through useful artifacts, technical discussion, and downstream projects.

## Growth loop

`DISCOVER → TRY → BUILD → SHARE → FEEDBACK → CONTRIBUTE → CITE`

## Community surfaces

- GitHub issues for actionable bugs and data problems.
- Pull requests for code, documentation, tests, and examples.
- Discussions, when enabled, for open-ended ideas, research, and showcase conversations.
- Technical communities where the project directly answers an existing question.

## Showcase: Built with RepoSource

A future community showcase can accept public projects that use the dataset. Inclusion should require actual use and a public link. Showcase inclusion is not endorsement, ranking, sponsorship benefit, or guaranteed promotion.

## Star policy

A star is an outcome of usefulness, not a campaign objective. Growth should follow genuine downstream value.

## Contribution loop

`DISCOVER → TRY → REPORT → CONTRIBUTE → REVIEW → MERGE → RELEASE`

Keep contribution paths lightweight. Good contributions include documentation, examples, validation improvements, tests, UX fixes, and research notes.

## Evidence

Prefer measurable evidence such as repository activity, issues, pull requests, downstream integrations, citations, community submissions, and reproducible analyses. Do not manufacture traction metrics.
